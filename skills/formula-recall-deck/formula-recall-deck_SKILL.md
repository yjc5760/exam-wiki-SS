# Formula Recall Deck（公式給／背分界記憶片）

## 這個 skill 產出什麼

給定一個單元的「公式給／背分界」頁，產出三個檔案，構成一支影片的完整素材：

| 檔案 | 用途 |
|---|---|
| `XX-Un-m_主題_公式給背分界_記憶片.pptx` | 可再編輯；旁白已寫入每頁「備忘稿」 |
| `XX-Un-m_主題_公式給背分界_記憶片.pdf` | 餵給 `pdf-narration-video` skill 做 TTS 配音影片的來源 |
| `旁白稿_XX-Un-m.md` | 逐頁旁白全文＋回想卡頁碼＋靜音插入指示 |

## 為什麼是「回想卡」，不是公式表

單純把公式排成表格做成影片，觀眾只會被動看過去，記憶效果接近零。這個 skill 的核心設計是把整份簡報改成**主動回想（active recall）**結構：

- **提問頁（深色）** 只出題不給答案，附提示與倒數圓點 → 影片播到這裡形成自然暫停點，觀眾先默寫。
- **解答頁（淺色）** 才給 LaTeX 公式，並在 `note` 放一句**記憶鉤**（口訣、物理直覺、檢查點），而不是重複公式本身。
- **三色分級**（🔴必背／🟠會給但別賭／🟢通常會給）貫穿全片，讓觀眾知道哪幾條才值得花力氣背。

寫每一頁時反覆問自己：*這一頁在要求觀眾動腦，還是只是在朗讀公式？* 如果是後者，改寫成提問。

## 工作流程

### 0. 建立工作目錄

```bash
mkdir -p ~/deck-XX-Un-m && cd ~/deck-XX-Un-m
cp <skill>/scripts/{lib.js,recall.js,gen_formulas.py,gen_diagrams.py,export_notes.py} .
npm install pptxgenjs
```

`lib.js` 與 `recall.js` 都用 `__dirname` 讀 manifest，必須跟 `deck.js`、`formula_manifest.json` 放在同一層。

### 1. 取得公式清單（最容易出錯的一步）

先 `web_fetch` 來源頁。**注意：頁面「二、主要公式逐條分界」的卡片與「三、逐年證據表」的資料列是 JS 動態渲染的，`web_fetch` 只會拿到篩選器與空表頭。**抓不到卡片內容是正常現象，不要當成頁面壞掉。

依序嘗試：

1. **本地知識庫**（最準）：若能存取 `exam-wiki-XX` 專案，直接讀 `raw/json/question_index.json`、`wiki/methods/*.md`，以及該 HTML 的原始碼中的 JS 資料陣列。
2. **請使用者提供**：請對方貼上 30 條卡片清單，或給檔案路徑。
3. **重建 + 揭露**：以頁面「一、判定方法」「四、背誦策略」的敘述為骨架，加上該科規範知識重建公式集與三色分級。**交付時必須明講哪些是重建的**，並請使用者校準。

無論走哪條路，**頁面 §4「背誦策略」是全片的靈魂**——它已經指出零容忍必背骨幹、有給也要判斷的陷阱、可以只背概念的少數幾條。這三塊直接對應簡報的骨幹頁、陷阱頁、綠色卡。

### 2. 規劃結構（動手寫程式前先規劃）

- 把公式歸成 4–6 個**家族**（如壓力 LRFD／壓力 ASD／有效長度／拉力／斷面），對應主題地圖頁。
- 挑 **6–10 條**做回想卡。挑選標準：紅色必背優先；有陷阱的橘色次之；綠色只挑「分岔判斷」型的（考它怎麼選，不考它怎麼寫）。條數太多影片會拖，太少沒有練習量。
- 挑 **3–5 個**需要圖解的公式。判準：有轉折點的設計曲線、有幾何量的斷面／破壞面、要比大小取捨的多個候選值。
- 指定穩定的公式 id（如 `lambda_c`、`fcr_new1`），之後 `gen_formulas.py` 與 `deck.js` 都用同一組 id。

詳細的逐頁藍圖見 `references/deck-blueprint.md`，完整可執行範例見 `references/example-deck-SS-U1-1.js`。

### 3. 渲染公式

填好 `gen_formulas.py` 的 `FORMULAS` 後執行。腳本內建兩道防呆：中文混進 `$...$`、以及 `\le`／`\ge`／`\tfrac` 這些 mathtext 不支援的巨集，會直接中止並指出是哪一條。

### 4. 渲染觀念圖

複製 `gen_diagrams.py` 填入自己的圖。這一步最需要真的懂題目，不能套模板。四個反覆出現的圖型與實作範例見 `references/deck-blueprint.md` 的「觀念圖四種原型」，完整可執行範例見 `references/example-gen_diagrams-SS-U1-1.py`。

**每一張圖都要用看圖工具實際看過再接進簡報。**標籤重疊在程式碼裡完全看不出來，而且幾乎每張有 3 個以上文字元素的圖都會發生。

### 5. 寫 deck.js

照 `references/deck-blueprint.md` 的頁序組裝。**每一頁都要 `s.addNotes(...)` 寫旁白**——旁白不是事後補的，是跟投影片同時想的，因為投影片上不該寫的話（口訣的來由、考古題年份的故事）都靠旁白講。

### 6. 建置與轉檔

```bash
node deck.js
soffice --headless --convert-to pdf "XX-Un-m_....pptx"   # 一次只轉一個檔
```

### 7. 匯出旁白稿

```bash
python3 export_notes.py "XX-Un-m_....pptx"
```

腳本會自動偵測回想卡頁、算出總字數與預估片長，產生 `旁白稿_XX-Un-m.md`。

### 8. 交付前目視 QA

```bash
pdftoppm -r 40 -png "XX-Un-m_....pdf" p
# 拼成一張 contact sheet 後用看圖工具檢查
```

檢查：沒有文字溢出卡片、沒有 `undefined`／`NaN`、公式圖沒有被壓到看不清（特別是速查表的寬公式）、每張回想卡的下一頁就是它的解答。

交付時要告訴使用者：**哪幾頁是回想卡、需要在旁白後插 3 秒靜音**——這是影片能不能產生記憶效果的關鍵設定，漏講整支影片就退化成朗讀。

## 六科的差異

符號慣例、常見公式家族、規範來源、口語唸法各科不同。動手前讀 `references/subjects.md` 對應的段落。

## 輸出慣例

- 檔名：`XX-Un-m_主題名稱_公式給背分界_記憶片.pptx` / `.pdf`、`旁白稿_XX-Un-m.md`
- 頁數：30–40 頁為宜（配音後約 12–18 分鐘），超過 45 頁應拆成上下集
- 一律同時產出 pptx、pdf、旁白稿三個檔，缺一個下一階段就接不上

## 陷阱

`references/pitfalls.md` 收錄了這條 pipeline 踩過的每一個坑（CJK 字型、mathtext 限制、速查表寬公式、LibreOffice 批次轉檔、圖表標籤重疊）。**動手前先讀一次**，不然會重踩。
