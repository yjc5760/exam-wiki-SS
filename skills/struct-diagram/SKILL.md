# 結構解題圖解產生器（struct-diagram）

## 為什麼用程式碼畫，不用 AI 生圖

工程圖只要角度、比例、箭頭方向錯一個，就是廢圖，而且錯得很難察覺。
擴散模型無法保證這些；程式碼可以。

本 skill 的三條鐵則，任何情況都不得違反：

1. **圖上的每個數字都必須來自解題結果**，不得憑印象填。
   反曲點在 $4L/7$ 是算出來的，不是畫到那裡剛好好看。
2. **圖必須能反映輸入的改變**。改一個 $EI$ 比值重跑，圖形要跟著變。
   若某段圖形是硬寫死的座標，那就是描摹，不是繪圖，必須重寫。
3. **每張圖都要能攔下一種特定錯誤**。寫圖說時必須說出它攔的是什麼。
   攔不下任何錯誤的圖就是裝飾，不要畫。

## 執行流程

### Step A：讀解題檔，決定要畫哪些圖

讀取使用者指定的 `.md`（如 `raw/solutions/SA-2025-1/SA-2025-1.md`）。

從解題內容判斷該畫哪幾張，**不要每題都畫五張**。判斷依據：

| 解題裡出現這種東西 | 就該有這張圖 |
|---|---|
| 原始附圖是截圖 | 題目重繪（向量版） |
| 「自由度」「忽略軸向變形」「消去」 | 自由度辨識圖 |
| 勁度矩陣、傾角變位法 | 單位位移狀態圖（矩陣每一行的物理意義） |
| 端點彎矩、反曲點、變形形狀 | 變形形狀 ＋ 彎矩圖 |
| 「相當於…的 70%」「介於…之間」 | 量級比較長條圖 |
| 桿力正負、零桿、挫屈檢核 | 桁架力流圖 |
| 主應力、最大剪應力、應力轉換 | 莫爾圓（2D 或三圓） |
| 中性軸、等值應力塊、$C_c = T$ | RC 斷面／應變／應力三聯圖 |
| $P_n$、$M_n$、平衡點、拉力／壓力控制 | P-M 交互曲線 |
| 剪力零點、彎矩極值 | 梁三聯圖（載重／SFD／BMD） |

完整對照見 `references/figure-catalog.md`（含六科各自的常見圖型與該用哪個 recipe）。

**在動手寫程式前，先把清單念給使用者聽**：打算畫哪幾張、每張攔什麼錯。
使用者可能只要其中兩張。

### Step B：把解題數字抓出來

逐一從 `.md` 的 §4／§5 抄出圖上會用到的每一個數值，寫成腳本頂端的常數區，
並在註解標明來源章節：

```python
# ── 由 SA-2025-1 §4.6 / §5.1 解得 ──
DELTA   = 5/84          # Δ·EI/PL³
THETA   = 3/5 * DELTA   # θ = 3Δ/(5L)，順時針為正
M_BASE  = 2/7           # M_AB / PL
M_TOP   = 3/14          # M_BA / PL
XI_INFL = M_BASE / (M_BASE + M_TOP)   # 反曲點 = 4/7，由彎矩線性內插算出
```

`XI_INFL` 這種寫法就是鐵則 1 與 2 的具體落實：它是算式，不是 `0.571`。

**若解題檔裡找不到某個數字，不要猜，回頭問使用者或先補算。**

### Step C：寫產圖腳本

在解題檔同層建 `gen_<題號>.py`，`sys.path` 指向本 skill 的 `scripts/`：

```python
import sys; sys.path.insert(0, "<skill>/scripts")
from structdraw import Canvas, C, compose, column_shape, beam_shape
from recipes import beam_vm, mohr3, rc_flexure, truss_forces, bar_compare
```

**優先用 `recipes.py` 現成的產生器**；不合用時才用 `structdraw.py` 的 primitives 自己組，
不要把 recipe 硬凹成不像樣。API 速查見 `references/API.md`。

### Step D：驗證

```bash
python3 <skill>/scripts/render.py figs/ --scale=2.0
```

這支腳本會做 XML 合法性檢查、**溢出檢查**、並輸出 2× PNG。
SVG 不會自動裁切，圖跑出畫布時檔案依然合法，只有溢出檢查抓得到。
**必須跑到 0 個需要修正才算完成。**

接著**實際看圖**：把 PNG 用 `view` 開起來檢查。至少確認這四件事：

- 文字有沒有互相重疊、有沒有被邊界切掉
- 中文有沒有變成方框（字型 fallback 失敗）
- 變形方向與轉角方向對不對（最常錯，見下方「符號約定」）
- 標註的數值與解題檔是否一字不差

沒看過圖就交付，等同沒做。

### Step E：插回 .md

把圖與圖說插到**對應章節的正下方**，不是全部堆在檔尾：

```markdown
![替代文字：說明圖的內容，供無障礙與搜尋使用](figs/SA-2025-1-fig-2-dof.svg)

*圖 2　自由度辨識。「忽略軸向變形」不是可有可無的簡化，它直接決定勁度矩陣是 3×3 還是 6×6。*
```

圖說的寫法規定：

- 一句話說圖在畫什麼，一句話說**它能攔下什麼錯**
- 不要重複算式（算式在內文已經有了）
- 用 `$…$` 寫符號，與該 .md 其餘部分的 LaTeX 慣例一致

最後在檔尾的日期行補記產生方式：

```markdown
*解析日期：YYYY-MM-DD　｜　圖解補繪：YYYY-MM-DD（向量圖，腳本 `gen_XX.py`，可重跑）*
```

### Step F：交付

用 `present_files` 一次遞出**全部**檔案：所有 `.svg`、所有 `.png`、更新後的 `.md`、產圖腳本。
只遞一部分，使用者那邊就會缺圖。

## 符號約定（最常出錯的地方）

轉角正負是本 skill 最容易出錯之處，**每張含轉角的圖都必須在圖上明寫採用哪一種**。

| 慣例 | 適用 | 耦合項 |
|---|---|---|
| 順時針為正（傾角變位法／多數中文教科書） | 與 $M_{nf} = \frac{2EI}{L}(2\theta_n + \theta_f - 3\psi)$ 相容 | $K_{13} = -6EI/L^2$ |
| 逆時針為正（一般矩陣結構分析） | 與能量法推導相容 | $K_{13} = +6EI/L^2$ |

兩者都對，但**必須與解題檔一致**。判斷方法：看解題檔的 $K_{13}$ 是正是負。

`structdraw.py` 的 `column_shape()` / `beam_shape()` **一律吃逆時針正**的轉角。
若解題檔用順時針正，傳入時要取負號：

```python
theta_ccw = -theta_cw_from_solution
```

**畫完務必目視確認**：側移向右的門型構架，柱應為雙曲率、節點隨側移方向轉動。
若圖上柱子彎成單曲率或反向，就是符號傳錯了。

## 檔案與命名

```
raw/solutions/<題號>/
├── <題號>.md              ← 插入圖片連結
├── gen_<題號>.py          ← 產圖腳本（隨解析一起版控）
└── figs/
    ├── <題號>-fig-1-frame.svg        + .png
    ├── <題號>-fig-2-dof.svg          + .png
    └── …
```

命名：`<題號>-fig-<序號>-<英文短語意>.svg`。
序號依插入 `.md` 的先後排，短語意用 `frame` / `dof` / `unit-states` / `deflected-bmd` /
`bmd` / `sfd` / `mohr` / `truss` / `section` / `pm` / `spectrum` 之類，看檔名就知道是哪張。

**兩種格式都要輸出**：SVG 給 HTML wiki 與 WeasyPrint，2× PNG 給 pptx 與影片管線。

`.md` 一律引用 SVG 的相對路徑。**不要**把圖 base64 內嵌進要進 repo 的 `.md`——
每改一次圖整個 diff 都會炸掉。若使用者要單檔攜帶版，另存一份 `-standalone.md`，
不要覆蓋原檔。

## 樣式規則

- 顏色**只能**用 `structdraw.C` 裡的色票，不要自己調色，六科才會一致。
  受拉紅／受壓藍／彎矩綠／剪力紫／變形藍／原始位置灰虛線／外力紅。
- 中文字型串 `FONT` 已含 fallback 鏈，不要改。數學符號用 `math()` / `math_px()`（襯線斜體）。
- 上下標寫 `σ_{1}`、`24EI/L^{3}`，**不要**用 `²` `³` `₁` 這類 Unicode 字元——
  數學襯線字型常缺這些字，會變方框或整個消失。
- 多聯圖用 `compose()`，它會自動加裁切遮罩，防止子圖互相侵入。
- 圖上文字用中文，符號用 LaTeX 風格；不要中英夾雜到難讀。

## 常見錯誤

| 症狀 | 原因 | 處理 |
|---|---|---|
| 中文變方框 | 環境缺 `Noto Sans CJK TC` | `apt-get install fonts-noto-cjk`；或只影響本機 PNG 預覽，SVG 進瀏覽器仍正常 |
| 上標不見 / 跑到旁邊 | 用了 `²` 或渲染器不支援 `text-anchor` + `tspan` | 改用 `^{2}` 語法；`_text_abs` 已自動把置中改為 start 錨點 |
| 圖形跑出畫布 | 標註槽寬度沒預留 | `render.py` 會抓；加大 margin 或把標註改放內側 |
| 子圖內容侵入隔壁格 | 直接拼接 `parts` 而沒用 `compose()` | 改用 `compose()` |
| 變形形狀方向相反 | 轉角正負慣例傳錯 | 見上方「符號約定」，`column_shape` 吃逆時針正 |
| 圖說寫成算式重複 | 沒想清楚這張圖攔什麼錯 | 重寫圖說；若真的攔不下任何錯，刪掉這張圖 |

## 相依套件

產生 SVG **不需要任何第三方套件**（純標準函式庫）。
只有輸出 PNG 需要 `cairosvg`：

```bash
pip install cairosvg --break-system-packages
```

沒裝也能跑，`render.py` 會略過 PNG 並提示。
