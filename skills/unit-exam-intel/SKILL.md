# unit-exam-intel — 單元命題情報頁產生器

回答一個很窄、但每次排讀書計畫都要問的問題：**這個單元到底考什麼？**

不是「這條公式長怎樣」（那是速查），也不是「為什麼成立」（那是講義），
而是**命題事實**：考幾題、佔多少、哪些考點在升溫、哪些空窗很久、下一次最可能考什麼。

這類事實有一個共同性質：**全部可以從 `raw/json/question_index.json` 重新算出來。**
所以本頁的鐵律是——**頁面上出現的每個數字，都要能由 `scripts/stats.py` 產生**。

**檔名規則：** `study/study-XX-Un-m.html`（沿用既有檔名，不要改名）

---

## 定位：與另外兩種 study 檔的分工

知識庫的 `study/` 下每個單元最多有三份教材，三者並存、互不覆蓋：

| | `lecture-XX-Un-m.html` | `formula-given-XX-Un-m.html` | `study-XX-Un-m.html`（本 skill） |
|---|---|---|---|
| 回答 | **為什麼**成立 | 這條公式**要不要背** | 這個單元**考什麼** |
| 內容 | 物理直覺、原理圖解、公式來源 | 30–40 條公式 × 逐年考卷證據 | 頻率、結構、漂移、清單、風險 |
| 資料來源 | wiki + 解析 + 規範 | `raw/exams/` 考卷原文 | `raw/json/question_index.json` |
| 可否自動重生 | 否（需人寫） | 半自動（需目視考卷） | **是（純資料驅動）** |
| 使用時機 | 第一次接觸該單元 | 排讀書計畫、決定背誦優先序 | 決定練題順序、考前押題 |
| skill | `unit-lecture` | `unit-formula-map` | **`unit-exam-intel`** |

> **⚠️ 若目標單元已有舊版 `study-XX-Un-m.html`**，它多半是早期的「七區段深度複習頁」
> （截面圖解／解題流程圖／公式速查／考題清單／高頻陷阱／互動計算器）。
> 這種舊頁與 lecture、formula-given 大量重複。處理方式見 **Step 6：舊頁遷移**，
> 不要直接覆蓋掉、也不要保留重複內容。

## Step 0：定位

1. 確認目前工作資料夾是哪一科（看 `CLAUDE.md` 開頭的科目代碼）。
   使用者講的單元代號科別與資料夾不符時，**先問清楚**，不要自行猜測切換。
2. 讀 `raw/json/syllabus_taxonomy.json` 取得該單元的**正式名稱**。
3. 確認 `study/` 下已存在哪些同單元教材，決定要放哪幾顆互連按鈕。

## Step 1：跑統計（不可跳過、不可手算）

```bash
python3 skills/unit-exam-intel/scripts/stats.py XX-Un-m
python3 skills/unit-exam-intel/scripts/stats.py XX-Un-m --json > /tmp/intel.json
```

`stats.py` 產出的欄位與頁面區塊一一對應：

| 欄位 | 用在哪 |
|------|--------|
| `totals.primary` / `secondary` / `share_pct` / `rank` / `rank_top3` | 出題概況 KPI |
| `years.exam_year_count` / `hit_year_count` / `gaps` / `recent6` | 出題概況 KPI 與註腳 |
| `drift.early` / `drift.late` | 考點漂移（前後對切） |
| `method.*` | 設計法／題型走向 |
| `tags_top` | 考點結構分群的素材 |
| `questions[]` | 考題清單（含主／副旗標、designMethod、tags） |

**這一步存在的唯一理由，是防止手打數字。** 真實教訓：SS-U1-1 舊頁的 KPI 寫
「近 6 年出題 6/6」，實際是 **4/6**（2019–2021 三年空白）；同頁另一處寫
「2022 起共 7 題」，實際 **6 題**。兩個錯誤都活了很久，因為沒有人會去重數 24 個年份。

> **`--json` 的輸出請留著**，Step 5 的驗證要拿它跟成品頁對帳。

## Step 2：決定「考點結構」的分群（唯一需要人判斷的一步）

`stats.py` 只給你標籤頻率，**不會替你分群**——因為分群要看該單元的知識結構，
不是統計問題。

**分群原則：**

- 目標 **3–6 群**，每群至少 2 題。少於 3 群代表切太粗，多於 6 群使用者記不住。
- 用**考生視角的解題套路**分，不要用標籤字面分。
  例：SS-U1-1 分成「拉力桿件／有效長度 K／柱挫屈強度／組合複合柱」，
  而不是把 `壓力桿件×14`、`有效長度×10` 這種高頻標籤直接當群名。
- **每題只歸一群**（取該題最主要的解題套路），這樣圓餅圖與篩選才不會重複計數。
- 每群配一個顏色與 emoji，全頁一致（KPI 卡、圓餅、堆疊長條、清單左邊框都用同一色）。

分群完成後，把 `moduleId → 群代碼` 的對照表記下來，Step 4 的 `Q[]` 陣列要用。

**其他科目的注意事項：**

| 科目 | 常見分群軸線 |
|------|------------|
| SS / RC | 構件類型（拉／壓／彎／剪）或極限狀態 |
| SA | 解法（力法／位移法／矩陣／影響線） |
| SD | 單自由度／多自由度／反應譜／規範耐震 |
| SM | 土壤性質／滲流／壓密／剪力強度／基礎型式 |
| MM | 應力分析／變形／能量法／挫屈／塑性 |

## Step 3：寫出六個區塊的內容

成果頁只有一個 `<section>`（標題就叫「命題分析」，**不加編號**），底下六個 `<h3>` 區塊。
六個區塊的小標**也不加編號**（早期版本用 1.1～1.6，已廢除）。

### 3-1　出題概況

四張 KPI 卡，數字全部抄 `stats.py`：

| KPI | 取自 |
|-----|------|
| 主考點題數（副考點另計） | `totals.primary` / `totals.secondary` |
| 佔全科比例 | `totals.share_pct` |
| 全科排名 | `totals.rank`，副標註明第二名是誰 |
| 近 6 考年出題年數 | `years.recent6.hit_years` / 6，副標寫共幾題 |

底下兩張 Canvas 圖：**年度分布堆疊長條**（依分群著色）＋**題型比例圓餅**。
兩張都只用主考點，並在圖標題註明「主考點 N 題」。

最後一段 `.note` 寫「三個要記住的數字」——把 KPI 翻譯成人話，
特別要點出**空窗年段**（`years.gaps`），並說明「空窗不代表退場」。

### 3-2　考點結構

Step 2 的 3–6 群，每群一張可點擊的卡片（點了篩選下方清單）。
卡片內容：emoji ＋ 群名（N 題）＋ 該群的代表性關鍵字 3–5 個。

### 3-3　考點漂移

把主考點依題號排序後**對切兩半**（`drift.early` / `drift.late`），
做一張「前段 vs 後段 × 各分群題數」的表，每列附一句**解讀**。

解讀要具體到題號，不要寫「近年較常考」這種空話。好的解讀長這樣：

> 對位圖／LeMessurier 近 12 年只出過 1 題（2023-1，且是概念題）；
> 最後一題計算型在 2013-2，已空窗 12 年

表後用 `.note` 收斂成**一句話**：這個單元的重心從 A 漂到 B，
並點出「若依歷史總題數分配複習時間會犯什麼錯」。這句話是本區塊的價值所在。

> **題數太少時（主考點 < 8 題）跳過本區塊**，改在出題概況的註腳寫一行趨勢描述。
> 6 題以下對切沒有統計意義，硬做會給出誤導性的結論。

### 3-4　設計法／題型走向

先看 `method.available`：

- **有 `designMethod` 欄位（SS、RC 等設計科目）**：做「期間 × LRFD／ASD／混合／概念題」表，
  三列＝前段、後段、近 6 考年。重點是回答「舊制度能不能跳過」。
- **沒有這個欄位（SA、MM 等）**：改用其他軸線，擇一即可——
  題型（計算／推導／說明）、解法（依 `tags_top` 歸納）、或單元內主題的年代分布。
  **不要留空區塊，也不要硬掰一個 designMethod 出來。**

表後 `.note` 寫「對複習的直接影響」，並連到 formula-given 頁（若存在）。

### 3-5　考題清單

**主考點與副考點都要列**，這是舊版最常見的缺漏。

每列包含：題號連結、設計法色籤、（副考點才有的）「副・所屬單元」灰籤、
一句話摘要、標籤串、狀態圖示（📄解析／📊互動圖／✅已驗證）。

篩選鈕：`全部` ＋ 每個分群一顆 ＋ `僅主考點` ＋ `僅副考點`。
**每顆鈕的括號數字要跟實際筆數相符**（Step 5 會驗）。

一句話摘要由你讀 `raw/solutions/XX-YYYY-N/XX-YYYY-N.md` 的標題與 §1 寫出，
控制在 20 字內，寫**這題在考什麼**，不是寫答案。

### 3-6　命題風險排序

依「歷史頻率 × 空窗年數 × 近年趨勢」排出 4–6 個考點，欄位：
風險等級、考點、歷史題數、最後出現、空窗年數、理由。三色底（高/中/低）。

**規則：**

- **理由必須引用具體題號與年數**，不可寫「常考」「重要」。
- **要誠實標示這是推測**，開頭寫一句「這是推測而非預言，用途是決定練題順序」。
- 最後 `.note` 寫「若只剩三天」的行動建議，並連到 lecture 的精選題章節（若存在）。

## Step 4：產生 HTML

複製 `skills/unit-exam-intel/reference/template.html` 當骨架，替換其中的
`{{...}}` 佔位與 `Q[]` 陣列。模板已含全部 CSS、篩選邏輯與兩張 Canvas 圖的繪製程式。

### 4-1　資料陣列格式（模板的 `Q[]`）

```javascript
// [題號, 分群代碼, 摘要, [標籤], 有互動圖0/1, 設計法, 主1/副0, 副考點的所屬單元]
["SS-2005-1","T","螺栓接合拉力桿件：淨斷面、剪力遲滯 U、塊狀剪力",
 ["剪力遲滯","U值","淨斷面斷裂"],0,"LRFD",1,""],
["SS-2012-3","K","梁柱 P-M 互制雙軸彎矩（斜撐構架 B1 放大法）",
 ["梁柱桿件","P-M互制","B1放大法"],0,"LRFD",0,"U1-3 梁柱"],
```

### 4-2　互連按鈕

只放**實際存在**的檔案。標準四顆（缺哪個就不放哪個）：

| 按鈕 | 連向 | 底色 |
|------|------|------|
| 觀念講義 📘 | `lecture-XX-Un-m.html` | `#6a1b9a` 白字 |
| 講義 PDF 🖨️ | `lecture-XX-Un-m.pdf` | `#f3e5f5` 紫字 |
| 給／背分界 🎯 | `formula-given-XX-Un-m.html` | `#c62828` 白字 |
| 分界 PDF 🖨️ | `formula-given-XX-Un-m.pdf` | `#ffebee` 紅字 |

按鈕上方放一塊 `.role` 黃底說明：本頁只回答什麼、三份教材的建議使用順序。

**不要放 Keynote 或課堂投影片按鈕**（使用者已明確要求移除）。

### 4-3　題號連結

一律指向 `problems-view/XX-YYYY-N.html`，並 `target="_blank"`。

**絕對不要用 `../index.html#md=raw/solutions/...` 這種舊式連結**——
那是把 `.md` 丟給瀏覽器，公式與附圖不會渲染，只會看到一堆純文字。

`problems-view/` 不存在時（其他科目可能還沒建），題號改成純文字並在頁尾註明原因，
順帶告知使用者可以先建渲染層。

### 4-4　同步 problems-view 的返回按鈕

若該科有 `study/problems-view/`，每頁 header 應有兩顆按鈕：

```html
<a class="quick" href="../study-XX-Un-m.html">&#128269; Un-m 命題分析</a>
<a class="lect"  href="../lecture-XX-Un-m.html">&#128218; Un-m 單元名 講義</a>
```

單元由該題的 `primaryTopicId` 決定（主分類沒有教材時退到第一個有教材的副分類）。
另在頁尾注入「跟隨來源單元」腳本：讀 `document.referrer`，若來源是
`study-`／`lecture-`／`formula-given-XX-Un-m.html`，就把兩顆按鈕同時改指向**來源那個單元**。
靜態 href 保底，JS 只做覆寫——無 JS 或無 referrer 時仍可用。

> 舊頁若還寫著 `href="javascript:history.back()"`，那顆按鈕在 `target="_blank"`
> 開的新分頁裡**按了不會有反應**（新分頁沒有上一頁歷史）。看到就一併換掉。

## Step 5：驗證（強制，不可略過）

產完頁後跑一次對帳，把 HTML 裡的 `Q[]` 與 `stats.py --json` 逐項比對：

```bash
python3 skills/unit-exam-intel/scripts/verify.py XX-Un-m
```

`verify.py` 會檢查七件事，任一不過就修到過：

1. `Q[]` 的題號集合 == `stats.py` 的主考點＋副考點集合（不多不少）
2. 每題的 `designMethod`、主／副旗標與索引一致
3. 篩選鈕括號內的數字 == 實際筆數（含「僅主／僅副」）
4. KPI 四個數字 == `stats.py` 對應欄位
5. 漂移表每列的前段／後段題數，加總 == 各半的題數
6. 題號連結全部指向存在的 `problems-view/*.html`（或全部為純文字）
7. 頁面沒有殘留 `../index.html#md=`、`javascript:history.back()`、區塊編號 `1.1`

驗證通過後，**再人工看一眼**這三件事（程式驗不出來）：

- 分群是否每題只歸一群、群名是否是考生看得懂的解題套路
- 漂移解讀與風險理由是否都引用了具體題號
- 有沒有把「推測」寫成「一定會考」

## Step 6：舊頁遷移（目標單元已有 study-XX-Un-m.html 時）

早期的 `study-*.html` 是七區段的「深度複習頁」。**不要直接覆蓋**，先做重疊盤點：

1. 逐區段比對 `lecture-XX-Un-m.html` 與 `formula-given-XX-Un-m.html` 的章節，
   列出「這個區段的內容在別處有沒有更好的版本」。
2. 典型結論（SS-U1-1 實例）：

   | 舊區段 | 重複於 | 處置 |
   |---|---|---|
   | ① 命題分析 | 無 | **保留並擴充成六區塊** |
   | ② 截面圖解 | lecture §1.1／§4.2／§8.1 | 刪，改連結 |
   | ③ 解題流程圖 | lecture §9 | 刪，改連結 |
   | ④ 核心公式速查 | formula-given §二（多了給／背證據，是上位版） | 刪，改連結 |
   | ⑤ 考題清單 | lecture §10（無篩選、無渲染頁連結） | **保留並補上副考點** |
   | ⑥ 高頻陷阱 | lecture §11 | 刪 |
   | ⑦ 互動計算器 | 唯一 | 與使用者確認去留 |

3. **有唯一內容的區段（如計算器）要問過使用者再刪**，不要自作主張。
4. **檔名不要改**——`lecture-*.html` 與 `formula-given-*.html` 都有連回 `study-*.html`，
   改名要同步三處，得不償失。
5. 遷移時順手核對舊頁的數字（十之八九有錯），錯了要在 log 裡寫清楚錯在哪。

## 常見錯誤

| 錯誤 | 後果 | 防法 |
|------|------|------|
| 手打統計數字 | KPI 錯很久沒人發現 | 一律跑 `stats.py`，`verify.py` 對帳 |
| 只列主考點 | 漏掉整批相關題（SS-U1-1 漏 7 題） | `Q[]` 必含 `secondaryTopicIds` 命中者 |
| 「近 6 年」算成「最近 6 個西元年」 | 遇到空窗年會多算 | 以 `exam_years[-6:]` 為準（考年，非西元年） |
| 題號連 `../index.html#md=` | 瀏覽器顯示未渲染純文字 | 一律連 `problems-view/` |
| 分群用標籤字面 | 群與群重疊、圓餅加起來超過 100% | 用解題套路分，每題只歸一群 |
| 漂移解讀寫「近年較常考」 | 沒有資訊量 | 引用題號與空窗年數 |
| 風險排序寫得像預言 | 誤導使用者 all-in 單一考點 | 開頭聲明是推測，用途是排練題順序 |
| 題數 < 8 硬做漂移分析 | 結論不穩且誤導 | 跳過該區塊 |
| 批次改檔用 `open(f,'w').write(re.sub(...))` | 例外時檔案被清成 0 bytes | 先算完字串再開檔寫入 |
